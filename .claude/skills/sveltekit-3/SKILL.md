# SvelteKit 3 / Svelte 5 rules (svelteMyAdmin)

The `svelte:svelte-core-bestpractices` and `svelte:svelte-code-writer` skills still apply for
component-level Svelte 5 code (runes, snippets, `{@attach}`, keyed each, `createContext`).
This skill **overrides** them wherever they assume SvelteKit 2. When unsure, fetch the official doc
with the svelte MCP `get-documentation` tool (e.g. "Migrating to SvelteKit v3", "hooks",
"Environment variables", "form actions", "remote functions") and validate every `.svelte` file with
`svelte-autofixer` (`npx @sveltejs/mcp svelte-autofixer <path>`).

## Config

- There is **no `svelte.config.js`**. All Kit options are passed to `sveltekit({...})` in `vite.config.ts`
  (top level, no `kit:` key): `adapter`, `compilerOptions`, `csrf.trustedOrigins`, `paths.origin`,
  `experimental.remoteFunctions`, `tracing`.
- Async Svelte (`await` in components) needs `compilerOptions: { experimental: { async: true } }` there.
- `tsconfig.json` extends `$app/tsconfig` and declares its own `include`/`exclude`.

## Imports & modules

- Use `#lib/...` with an explicit extension (`import { escapeId } from '#lib/server/db/escape.ts'`),
  never `$lib` (no longer generated). Declared in `package.json` `imports`.
- `$app/state` only (`page`, `navigating`, `updated`); `$app/stores` is gone.
- `$app/env` replaces `$app/environment` (`browser`, `dev`, `version`).
- Env vars: `$app/env/private` / `$app/env/public`, declared with `defineEnvVars` from
  `@sveltejs/kit/env` (`$env/*` is deprecated). Undeclared vars read as undefined.
- Server-only: any file with a `server` segment (`x.server.ts`, `server.ts`) or inside **any** `server/`
  directory outside `src/routes`.
- Hook types from `@sveltejs/kit/hooks` (`Handle`, `HandleServerError`); param matchers in a single
  `src/params.ts` via `defineParams` from `@sveltejs/kit/params`.

## APIs that changed

- Responses: `Response.json(data)` / `new Response(text)` — `json()`/`text()` are deprecated.
- `error(status, 'message', { ...extra })` — second argument is always a string.
- `handleError` receives **all** errors (including `error(...)` ones); log only unexpected/5xx.
  It may return `status`. `App.Error` always has `status`.
- `redirect()` to another origin needs `{ external: true }`.
- `goto(url, { replace, reset: false, refreshAll, shallow, state })`; `goto` rejects for non-app URLs.
  `refreshAll()` instead of `invalidateAll()`. `pushState/replaceState` → `goto(..., { shallow: true })`.
- `$app/paths`: `resolve('db/[db]', { db })` (no leading `/` for paths; route ids keep it) and
  `asset('x.png')`; `base`/`assets`/`resolveRoute` are removed.
- `page.url` is read-only — copy with `new URL(page.url.href)` before mutating.
- `fail(400, ...)` status is now the real HTTP status of enhanced form responses.
- `use:enhance` on a form whose `action` targets another page navigates there.
- Cookies: `cookie` v2; `path` defaults to `/`; ASCII names only.
- `data-sveltekit-*="false"` (not `'off'`). 204 responses have no body.
- Remote functions (`*.remote.ts`) are experimental; we use form actions + `+server.ts` endpoints
  unless the orchestrator decides otherwise. Remote forms require `field.as(...)` spreads.

## Svelte 5.57 component rules (summary)

- Runes only: `$state`, `$state.raw` for big replaced data (query results!), `$derived`/`$derived.by`,
  `$props`, `$bindable`; `$effect` only as a last resort.
- Snippets + `{@render}` instead of slots; `onclick` not `on:click`; `{@attach}` not `use:`;
  clsx arrays/objects in `class` instead of `class:`; `<Comp>` instead of `<svelte:component>`.
- Shared state: classes with `$state` fields exposed via `createContext` — never module-level
  mutable state on the server (leaks between users).

## UI: shadcn-svelte

- Components live in `src/lib/components/ui/<name>/` (generated by the `shadcn-svelte` CLI, then owned
  by us). Add new ones with `pnpm dlx shadcn-svelte@latest add <name>`; do not hand-roll a component
  that shadcn-svelte provides (button, input, select, dialog, dropdown-menu, table, tabs, sidebar,
  sonner, tooltip, checkbox, command, popover, …).
- Built on bits-ui 2 + Tailwind v4; use the `cn()` helper from `#lib/utils.ts` and the theme tokens
  in `src/app.css` (`bg-background`, `text-muted-foreground`, …), never raw colours.
- Icons: `@lucide/svelte`.
- The CLI emits imports like `#lib/utils.ts.js` / `#lib/components/ui/x/index.js`; after every
  `shadcn-svelte add`, rewrite them to `#lib/...ts` (relative `./x.js` imports are fine).
- `cn()` is re-exported from the `cn` package in `#lib/utils.ts` (no direct clsx/tailwind-merge deps).
- There is no `data-table` registry item; `@tanstack/table-core` is **v9** — check its API (the shadcn
  docs pattern targets v8) before building data tables.
