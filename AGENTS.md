# svelteMyAdmin — conventions for implementer agents

A SvelteKit + Svelte 5 re-implementation of phpMyAdmin 5.2.3. Read `docs/ROADMAP.md` first
(architecture, routing tree, phases). PHP reference sources: `../phpMyAdmin-5_2_3` (read-only, never modify).

## Stack

SvelteKit (adapter-node), Svelte 5 **runes**, TypeScript strict, Tailwind CSS v4, shadcn-svelte (bits-ui 2) + mode-watcher, zod, mysql2/promise,
Vitest, Playwright, pnpm, Node >= 22.

## Folder layout

```
src/
  app.css                  Tailwind + shadcn-svelte theme tokens (CSS variables, class-based .dark on <html>)
  lib/
    components/ui/         shadcn-svelte components (generated by the CLI, then owned by us)
    components/            our own composed components (theme-toggle, app shell, ...)
    hooks/                 shared hooks (.svelte.ts), e.g. is-mobile
    utils.ts               cn() and shadcn type helpers
    server/                SERVER-ONLY code (never import from client code)
      config/              config.json loader + zod schema (same keys as phpMyAdmin $cfg)
      auth/                auth plugins (cookie, config, http)
      db/                  connection, escape.ts, splitter.ts, metadata services
      pmadb/               configuration storage (pma__* tables)
      export/ import/      plugin registries
  routes/                  mirrors phpMyAdmin routes, see ROADMAP "Routing"
e2e/                       Playwright specs (*.e2e.ts)
docker/initdb/             DB fixtures (sma_test) + phpMyAdmin create_tables.sql (verbatim)
config.sample.json         committed sample; config.json is git-ignored (override path: SMA_CONFIG)
```

## Rules

- **Svelte 5 runes only**: `$state`, `$derived`, `$effect`, `$props`, snippets, `{@render}`. No `export let`,
  no `$:`, no `on:click` (use `onclick`), no `<slot>`, no Svelte stores unless a genuinely shared
  cross-component subscription is required (prefer `.svelte.ts` modules with `$state`).
- Use the Svelte MCP `svelte-autofixer` on every new/changed `.svelte` file.
- **Server-only code lives in `src/lib/server/`** (SvelteKit blocks client imports). Never expose
  passwords, `blowfish_secret` or raw errors to the browser.
- **Validate all input with zod** (form actions, `+server.ts`, query params). Parse, don't trust.
- **Always escape identifiers with `escapeId`/`escapeQualified`** and values with `quoteValue`/`escapeString`
  from `#lib/server/db/escape.ts`. Prefer `?` placeholders (`conn.execute`/`query(sql, params)`) for values.
  Never build SQL by string concatenation of user input. Split multi-statement SQL with
  `splitStatements` (`db/splitter.ts`); connections have `multipleStatements` off.
- Keep config key names identical to phpMyAdmin's `$cfg` (see `libraries/config.default.php`).
- Style: tabs, single quotes, no trailing commas (Prettier enforces it: `pnpm format`).
- Imports: only the `#lib/*` alias (package.json `imports`) with explicit extensions, e.g.
  `import { cn } from '#lib/utils.ts'`. Never `$lib` (not generated in SvelteKit 3).
- **Before writing any Svelte/SvelteKit code, load the project skill `.claude/skills/sveltekit-3/SKILL.md`
  plus the svelte plugin skills** (`svelte:svelte-core-bestpractices`, `svelte:svelte-code-writer`); the
  project skill wins wherever they assume SvelteKit 2.
- **UI = shadcn-svelte.** Use the components in `#lib/components/ui` (bits-ui 2 based); add missing ones with
  `pnpm dlx shadcn-svelte@latest add <name>` (then fix generated imports to `#lib/...ts` if needed). Do not
  hand-roll what shadcn-svelte provides. Icons come from `@lucide/svelte` (`@lucide/svelte/icons/<name>`).
  Style only with theme tokens (`bg-background`, `text-foreground`, `text-muted-foreground`, `border`,
  `bg-primary`, ...), never raw colours. Light/dark/system via `mode-watcher` (`ModeWatcher` in the root layout).

## i18n

All user-visible UI strings must go through `t()` / `tn()` / `tc()` (`const { t, tn, tc, fmt } = useI18n()` from
`#lib/i18n/index.ts`; server code: `locals.i18n.t()`). English text is the key; whole sentences, `{params}`
instead of concatenation, `tn` for plurals, never translate SQL, identifiers or MySQL error messages.
Catalogs are `src/lib/i18n/locales/<lang>/<area>.json` (area = path of the source file); after adding strings run
`pnpm i18n:extract`, `pnpm i18n:import-mo fr|es`, fill the rest in `fr`/`es` by hand and `pnpm i18n:check --ci`
(`pnpm test` fails on incomplete `fr`/`es` catalogs). Do not name variables `t`. Full rules and the area mapping:
`docs/I18N.md`.

The look (grey canvas, white rounded cards, indigo primary, soft status pills) is specified in

## Tests are mandatory with every feature

| Kind        | File name                    | What                                                                                                 |
| ----------- | ---------------------------- | ---------------------------------------------------------------------------------------------------- |
| Unit        | `*.test.ts` next to the code | pure logic (parsers, escaping, formatting, config)                                                   |
| Component   | `*.svelte.test.ts`           | Svelte components in a real browser (`vitest-browser-svelte`)                                        |
| Integration | `*.integration.test.ts`      | SQL against Docker MySQL 8.4 (:33306) / MariaDB 11.4 (:33307); must skip gracefully when unreachable |
| E2E         | `e2e/*.e2e.ts`               | critical user flows (Playwright)                                                                     |

Never weaken or delete a test to make it pass: fix the code.

Test conventions (specs run in parallel workers against shared Docker databases):

- **Temporary databases are named `tmp_<suite>_...`** (e.g. `tmp_t3a_e2e`, `tmp_t3c_int_33306`), integration
  AND e2e. Never `sma_*`: the sidebar groups databases by the `_` separator, so an `sma_...` temp db would
  move the fixture `sma_test` into an `sma` group and break other specs. Only the fixture is `sma_test`.
- **Scope e2e locators** to `page.getByRole('main')` (or a `data-testid`/dialog/row) instead of the whole
  page: the sidebar tree, breadcrumbs, tab bar and command palette repeat table/db names, and strict mode
  fails on duplicates. Specs that touch server-global state (`event_scheduler`, `max_connect_errors`, ...)
  must restore it in `finally` and live alone in their file (files run in parallel, tests within a file serially).
- **e2e: always navigate with `gotoReady(page, url)`** from `e2e/helpers.ts` (`page.goto` + wait for
  `html[data-hydrated="true"]`, set by the root layout); use `login`/`reloadReady` from there too. Never use
  `page.goto` directly, `waitForTimeout`, `networkidle` or `toPass` retry loops to mask hydration races.
- **JS-dependent controls are disabled until hydrated**: `app.css` makes non-submit buttons and bits-ui
  checkbox/select/tab/menu roles inert (`pointer-events: none`) until `html[data-hydrated]`; submit buttons whose
  payload is built client-side must use `disabled={!hydration.ready}` (`#lib/hooks/hydration.svelte.ts`).
  Native `<form method="POST">` must work as plain HTML: every value the action reads needs a real `name`d
  control or hidden input rendered by SSR (no state that only exists in client JS).
- Do not rely on form fields being pre-filled with the current name; name inputs use a `placeholder`.

## Commands

```
pnpm install
pnpm check               # svelte-check (types)
pnpm lint                # prettier --check + eslint
pnpm format              # prettier --write
pnpm test                # unit + client (browser) projects, run once
pnpm test:unit           # unit only
pnpm test:integration    # needs `pnpm db:up`
pnpm test:e2e            # Playwright (builds + previews the app; `pnpm exec playwright install chromium` once)
pnpm build
pnpm db:up / db:down     # docker compose (mysql :33306, mariadb :33307, root/root, fixture db sma_test,
                         #  config storage db `phpmyadmin`, control user pma/pmapass)
```

Done = `pnpm check && pnpm lint && pnpm test && pnpm build` green (+ integration when DB is up).

## Compatibility with phpMyAdmin (from ROADMAP)

1. Config keys identical to `$cfg` (JSON `config.json` instead of `config.inc.php`).
2. Configuration storage uses the exact `pma__*` tables from `sql/create_tables.sql`; both apps must be able
   to share one pmadb. Feature-detect per table.
3. Export formats byte-compatible where practical (SQL dump header/structure, CSV, JSON, XML).
4. Legacy `index.php?route=/table/sql&db=x&table=y` URLs redirect to the new paths.
5. Auth types `cookie`, `config`, `http` (+ `signon` later), `AllowNoPassword`, `AllowRoot`, `AllowDeny`.
