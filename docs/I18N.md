# Internationalisation (i18n)

gettext-style: the **English text is the key**. A missing or empty translation falls back to English, so a
half-translated language never breaks the UI. Catalogs are flat JSON files; phpMyAdmin's compiled `.mo`
translations (`../phpMyAdmin-5_2_3/locale/<lang>/LC_MESSAGES/phpmyadmin.mo`) can be imported.

Languages today: English (source), French (`fr`), Spanish (`es`).

## Writing translatable strings

```svelte
<script lang="ts">
	import { useI18n } from '#lib/i18n/index.ts';
	const { t, tn, tc, fmt } = useI18n(); // destructuring is fine: reactive to language switches
</script>

<h1>{t('Databases')}</h1>
<p>{t('Table {table} has been dropped.', { table: name })}</p>
<p>{tn('{n} row affected.', '{n} rows affected.', count)}</p>
<button>{tc('verb', 'Export')}</button>
<span>{fmt.bytes(size)} - {fmt.number(rows)} - {fmt.date(created)}</span>
```

| Function                       | Use                                                                                                 |
| ------------------------------ | --------------------------------------------------------------------------------------------------- |
| `t(msgid, params?)`            | whole sentence/label; `{name}` placeholders                                                         |
| `tn(singular, plural, n, p?)`  | plurals; `{n}` is always available; the **singular** is the catalog key                              |
| `tc(context, msgid, params?)`  | same English text, different meaning (gettext `msgctxt`)                                            |
| `N_(msgid)`                    | marks a string for extraction without translating it (module-level constants); call `t(x)` later    |
| `fmt.*`                        | locale-aware numbers (`number`, `numberFormat`, `si`), bytes (`bytes`, `byteDown`), `timespan`, `date`, `dateTime`, `monthNames` |

Server code (`+page.server.ts`, endpoints, hooks) uses `locals.i18n.t(...)` (same API, `locals.locale` is the code).
Code outside a component that cannot call `useI18n()` takes a `Translator` (or the translated strings) as an argument.

Rules:

1. **Whole sentences.** Never build a sentence by concatenation (`t('Delete') + ' ' + name`): word order differs
   between languages. Use params: `t('Delete {name}?', { name })`.
2. **Literal arguments only.** The extractor reads string literals (`'...'`, `"..."`, `` `...` `` without `${}`, or literals
   joined with `+`). `t(someVariable)` is reported as a warning and not extracted: use `N_('...')` where the
   literal is declared. Add `// i18n-ignore` on a line, or `i18n-ignore-file` in a file, to skip it.
3. **Plurals with `tn`**, never `count === 1 ? t('row') : t('rows')`. Languages have up to six plural forms (French treats 0 as singular).
4. **Context with `tc`** when one English word translates differently by role (`tc('verb', 'Export')` vs `tc('noun', 'Export')`).
5. **Do not translate** SQL keywords/statements, identifiers (database/table/column names), MySQL/MariaDB error
   messages, config key names, file formats, or code. Translate the UI around them.
6. **Keep phpMyAdmin's exact English wording** where the UI mirrors phpMyAdmin (e.g. `Databases`
   gets its French translation for free) so `i18n:import-mo` matches the msgid. phpMyAdmin's `%s`/`%d`/`%1$s` correspond to our `{name}`
   (see "Placeholder matching" below), so a message like `Table %s has been dropped` is matched by `Table {table} has been dropped`.
7. **Do not name a variable `t`** (loop variables, helpers): it shadows the translation function and confuses the
   extractor. (`{#each tabs as tab}`.)
8. No HTML in messages. Use separate snippets / `<a>` around `t()` calls for links and emphasis.
9. Do not translate `data-testid`, `aria` ids or route names. `aria-label`/`placeholder`/`title` are translated.
10. Numbers and dates shown to users go through `fmt` (separators `,`/`.`, byte units and month names come from the active locale).

## Catalog layout

```
src/lib/i18n/locales/<lang>/<area>.json     flat { "msgid": "translation" }
```

- Key = English msgid. With a context: `"context\u0004msgid"` (JSON escape `\u0004`, like gettext).
- Value = string, or an **array of plural forms** for `tn` entries, ordered by the language's CLDR plural categories
  (`zero, one, two, few, many, other`, only those the language has): `en` = `[one, other]`, `fr`/`es` = `[one, many, other]`,
  `ru` = `[one, few, many, other]`. `Intl.PluralRules` selects the form at runtime.
- The `server` area is stored as `server-pages.json` (SvelteKit refuses to bundle a module named `server.*` into the client).
- `en/<area>.json` is generated (key = value; plurals `[singular, plural]`) and is the reference for the checker; it is not loaded at runtime.
- An empty string (or empty plural form) means "not translated yet": runtime falls back to English, `i18n:check` fails for `fr`/`es`.
- Files are sorted and tab-indented by the tooling: do not hand-format them (`locales/` is prettier-ignored).
- The runtime merges every area file of the active language; only the active language is downloaded by the browser.

### Areas and the file -> area mapping

The area is decided by the **path of the source file that contains the `t()` call** (`scripts/i18n/areas.ts`, first match wins):

| Area       | Source files                                                                                                                         |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `io`       | `components/{export,import}`, `lib/import`, `lib/server/{export,import}`, any route under `export/` or `import/`, `api/import`        |
| `admin`    | `components/{privileges,preferences,two-factor,monitor,designer}`, `lib/{advisor,designer,gis,monitor,preferences,two-factor}`, `lib/sql/{privileges,normalization}*`, `lib/server/{privileges,designer,two-factor,preferences}`, routes `server/{privileges,settings}`, `server/status/{monitor,advisor}`, any `privileges/`, `designer/`, `gis/`, `normalization/` route, `login/2fa` |
| `sql`      | `components/{sql,sql-editor,query}`, `lib/server/sql`, `lib/sql/{editor,bookmark,history,classify,messages,run-types,limit,statement,templates,tokens,query-schema,qbe,multi-table-query,result-sort,db-search,escape}*`, `api/sql`, any `sql/` or `query/` route |
| `server`   | routes `(app)/server/**` (rest), `lib/admin`, `lib/server/{admin,pmadb}`                                                             |
| `table`    | `components/{table,table-search,table-structure,columns,results,tracking,transformations}`, `lib/{table,tracking,transformations,sql}` (rest), `lib/server/{table,transformations}`, routes `db/[db]/table/**`, `db/[db]/central-columns`, `transformations`, `api/central-columns` |
| `database` | `components/database`, `lib/server/database`, routes `db/**` (rest)                                                                  |
| `shell`    | `hooks.server.ts`, `app.html`, routes `login`, `logout`, `+*` files of `routes/` and `routes/(app)/`, `api/{navigation,health,lang}`, `components/{app-shell,home,navigation,console,i18n,theme-toggle}`, `lib/nav`, `lib/server/{auth,navigation,routing,config,db,i18n}` |
| `common`   | everything else: `components/ui`, `lib/i18n`, `lib/format.ts`, `lib/forms`, `lib/hooks`, `lib/chart`, ...                            |

Because the area follows the file, **each area's work only touches `locales/*/<area>.json`**: agents working on different
areas never edit the same catalog file. A string used from several areas is simply listed in each area's catalog
(`i18n:extract` copies an existing translation of the same key instead of leaving it empty).

## Tooling (`pnpm i18n:*`, plain Node, TypeScript run natively)

| Command                                   | What                                                                                                                       |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `pnpm i18n:extract [--prune] [--area=a,b] [--dry-run]` | scans `src/**/*.{svelte,ts}` (not tests) for `t/tn/tc/N_` literals, writes `en/<area>.json`, adds missing keys (empty) to every other language, warns about non-literal calls. `--prune` removes obsolete keys |
| `pnpm i18n:import-mo <lang> [--area=a,b] [--overwrite] [--list-missing] [--mo=path]` | fills empty translations from phpMyAdmin's `.mo`, prints coverage per area |
| `pnpm i18n:check [--ci] [--area=a,b] [--warnings]` | per-language coverage per area. `--ci` (or `CI=true`) exits 1 if `fr`/`es` lack a key, have an empty translation, a plural array of the wrong length, or `{params}` that differ from English |

`pnpm test` also runs the checker over the shipped catalogs (`scripts/i18n/i18n-tools.test.ts`), so a broken or
incomplete `fr`/`es` catalog fails the unit tests. While several people work in parallel, scope everything to
your area: `I18N_AREAS=table pnpm test:unit` / `pnpm i18n:check --area=table`.

Typical loop for an area `X`:

```sh
# 1. wrap strings with t()/tn()/tc() in the files of area X
pnpm i18n:extract --area=X
pnpm i18n:import-mo fr --area=X && pnpm i18n:import-mo es --area=X   # free translations from phpMyAdmin
# 2. translate what is left by hand in locales/{fr,es}/X.json (pnpm i18n:check --area=X lists the gaps)
pnpm i18n:check --ci --area=X
```

### Placeholder matching in `import-mo`

1. Exact msgid (and msgctxt) match: the translation is copied verbatim.
2. Otherwise both sides are normalised: phpMyAdmin's `%s`, `%d`, `%1$s`, `%2$d` and our `{name}` all become one marker;
   `%%` becomes `%`. If the normalised texts are identical and the phpMyAdmin entry is unique, the k-th placeholder
   of the phpMyAdmin msgid is paired with the k-th `{name}` of ours (`%N$s` uses slot N). The translation's placeholders
   are rewritten through that pairing, so reordered translations (`%2$s ... %1$s`) stay correct.
3. Skipped (left empty): repeated `{name}` in our msgid, printf conversions other than `%s`/`%d` (`%.2f`, `%5s`), ambiguous
   matches, plural vs singular mismatches.
4. Plural forms are mapped from gettext's `Plural-Forms` expression to CLDR categories by evaluating the expression for a sample `n` of each category.

## Adding a language

Example: German (`de`).

1. `src/lib/i18n/languages.ts`: make sure there is an entry (all 45 phpMyAdmin languages are already listed with native name, English name,
   `dir` and `Intl` locale; add one line for anything else: `l('xx', 'Native', 'English', { dir: 'rtl' })`).
2. Create `src/lib/i18n/locales/de/` and run `pnpm i18n:extract` (creates empty `de/<area>.json` files for every area with keys).
3. `pnpm i18n:import-mo de` imports what phpMyAdmin already translated (`pma` folder name, e.g. `pt_BR`, comes from the registry).
4. Translate the rest by hand; `pnpm i18n:check` shows coverage. To make the language mandatory in CI, add it to `STRICT_LANGS` in `scripts/i18n/lib.ts`.
5. Done: the language is auto-discovered from the folder (login select, Appearance settings, `Accept-Language` negotiation, `<html lang dir>`).
   Separators and units come from the catalog keys `","`, `"."`, `"B"`, `"KiB"`, ... in `common.json`.

## Runtime

- `locals.locale` / `locals.i18n` are set in `hooks.server.ts` (`localeHandle`, refined after the user's preferences load).
  Resolution order (`src/lib/i18n/resolve.ts`): cookie `sma_lang` -> user preference `lang` -> config `DefaultLang`
  (when not the schema default `en`) -> `Accept-Language` -> `en`.
- `<html lang dir>` come from `%lang%` / `%dir%` in `app.html`.
- The root `+layout.server.ts` passes `{ locale, languages }`; the universal `+layout.ts` loads the merged catalog (server and browser);
  `+layout.svelte` provides an `I18n` instance through context (`createContext`; no module-level state, safe for SSR).
- Switching language: `setLanguage(code)` (`#lib/i18n/switch.ts`) -> `POST /api/lang` (sets the cookie, saves the `lang` preference for
  logged-in users) -> `refreshAll()`; every string re-renders without a full reload. Use `<LanguageSelect id="..." />`
  (`#lib/components/i18n/language-select.svelte`) anywhere a language choice is needed.
- Components rendered without a layout (unit/component tests, error pages) get plain English.
